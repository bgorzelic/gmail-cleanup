# After-action report — v0.6.0 release and first live cleanup

**Date:** 2026-09-30 · **Scope:** cut v0.6.0, publish to PyPI, improve the tool, clean one real inbox with it.

## Outcome

| | Start | End |
|---|---|---|
| Inbox | 3,933 conversations, 3,516 unread | 520 conversations, 328 unread |
| Release | v0.5.2, GitHub only | v0.6.0 on PyPI as `gmail-inbox-cleanup` |
| Tests | 185 | 221 |
| Unsubscribed senders on record | 121 | 352 |

Nothing was deleted from mail; every inbox change was an archive.

## Timeline

1. Release prep found two blockers: the PyPI name `gmail-cleanup` was taken, and the wheel installed a top-level `lists/` directory and would have shipped personal lists.
2. Lists split into packaged seeds + `~/.gmail_cli/lists/`; `verify` fixed; autopilot flags added; PR opened.
3. First live dry run → 9 account/finance/health senders were unprotected → added to the personal keep list.
4. Live autopilot (30 days), then the whole inbox (125 days), then a manual archive by Gmail category.
5. Along the way: batching, quota pacing, rate-limit handling, and four more bug fixes.
6. Merged, tagged, published via trusted publishing, verified by installing from PyPI.

## Bugs found (all pre-existing)

| Bug | Impact | Fix |
|---|---|---|
| `verify` counted mail sent before the unsubscribe | Daily `--escalate` would auto-trash senders unsubscribed the day before | Count only mail after `unsubscribed_at` + grace; PENDING bucket |
| `humans.yaml` not enforced in `unsubscribe` | A real person with a List-Unsubscribe header could be unsubscribed | Humans checked first, before the kill list |
| `has:list` filter | Not a Gmail operator; matched nothing for months | Removed |
| Filters deduped by exact `from:` string | One more filter per run | Replace the covered filter |
| `status` paged 10k message IDs twice | Wrong numbers, wasted quota | One `labels.get` call |
| API errors returned empty results silently | Throttled calls looked like "no mail" | Retry + report |
| Wheel layout | `site-packages/lists/`, writes into the package | Seeds inside the package; writes to `~/.gmail_cli/` |

## Mistakes made during the session

- **Tests wrote to the real home directory.** Moving list writes to `~/.gmail_cli/` while tests only redirected the seed directory appended 14 test addresses to the real `unsubbed.yaml`. Restored from git; tests now sandbox `HOME` at import and per test.
- **Wrong quota numbers.** Pacing was first built on `messages.get` = 5 units / 250 units/s. Google's page says 20 and 100. One 35-second scan ran ~10× over the documented rate before this was checked.
- **A test passed locally and failed in CI** because import-time constants read the developer's real lists. Same root cause as the first item.
- **The list split would have broken `filters apply` on fresh installs** (empty `from:`). Caught before release.
- **`quotaExceeded` was briefly made retryable**, copied from another project without checking Google's error guide. Reverted: an exhausted quota now stops the run.

## What worked

- Dry run before every live run.
- CI on three Python versions with a sandboxed home.
- Reading how other tools (hush, inbox-zero, gmail-cleaner) pace Gmail calls, then checking Google's own pages rather than trusting either.
- Writing an undo manifest before bulk changes made outside the CLI.

## Lessons

1. **Read the provider's current quota and error pages.** Remembered numbers and other projects' constants were both wrong.
2. **A documented guarantee needs a test that fails without it.** "Humans always win" was in the README for months and enforced nowhere.
3. **Tests must never be able to see the real home directory** — not at import time either.
4. **Gmail search cannot see headers.** Anything that depends on `List-Unsubscribe` must fetch headers.
5. **Concurrency is a separate limit from rate.** 50-wide batches were throttled at a rate that 25-wide batches were not.
